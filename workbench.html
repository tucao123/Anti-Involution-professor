J1 / 找方向 · 冷启动不需要任何授权数据

放在一起比。

粘 5–10 份你正在考虑的岗位描述。系统只做「在这几份里」的比较，告诉你哪些要求反复出现、哪份的要求最接近你已有的经历、补起来最省力的是哪个。不做行业大盘，不写「普遍如此」。

J2 / 做核对 · 核心步骤

把要求逐条
对上你的证据。

一条条判「有证据 / 待核实 / 明确缺口 / 未知」。学历、届别、地点这类硬条件单独标出，不被其他技能抵消。没有百分比总分——因为一个数字制造不了依据，只会制造虚假的确定。

J2→J4 / 定行动 · 按差距类型分流

下一步做什么，
分清是哪一种缺口。

缺表达、缺证据、缺能力、缺硬条件，四类动作完全不同。「证据够了，先投」和「这个方向先放弃」都是合法结论——这里不制造「必须补完才能投」的焦虑。

先在「做核对」生成一次对照表，行动建议会基于那一版的判断。
J3 / 过追问 · 只针对一个缺口

围绕真实项目，
被追问三层。

选一条岗位要求，配一段你真实做过的项目。系统连续问三层：做了什么 → 为什么这么做 → 重来怎么改。反馈只引用你刚才的原话，指出哪里空、哪里是判断。压力模式是可选训练，不是默认。

J4 / 看反馈 · 唯一让人反复回来的入口

投出去了，
记下这一笔。

岗位、投递时间、投的是哪版简历、走到第几轮、结果。很轻，但两周后没回音时，你能回到对照表发现「原来是简历版本投错了」。看板只存在这台设备的浏览器里，由你自己保存和删除。

About / 数据边界与口径

能核对的账，
才敢让你照着做。

四条不动的边界
样本内没有授权数据就不给市场级结论；用你自己的 JD 做对比时，明确写「在你提供的样本内」。
不出本机用户材料默认不保存；保存、外发都要单独确认；删除会说明范围——已发出的内容本地删除 ≠ 外部撤销。
不爬取自动爬取与自动截图执行体已移除；知识只由管理员提供文本或截图（本地 OCR），系统不访问第三方页面。
不制造焦虑不承诺录用、不预测薪资；「先投」和「放弃」都是合法结论。
